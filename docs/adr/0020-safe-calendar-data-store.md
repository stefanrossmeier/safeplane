# ADR 0020: Calendar store uses append-only JSONL

## Status

Accepted

## Context

Safeplane needs a local calendar data store before giving agents or connectors calendar capabilities.

Calendar data is durable user data.

It must be separated from disposable traces, artifacts, and temporary runtime state.

The storage layer should be easy to inspect, back up, and recover during early phase development.

## Decision

Phase 8 introduces a local calendar store under:

    SAFEPLANE_HOME/data/calendar

The source of truth is an append-only JSONL event log:

    events.jsonl

A rebuildable materialized index is stored as:

    index.json

Snapshots are stored under:

    snapshots/

Calendar operations are deterministic CLI commands.

The assistant does not get calendar access in phase 8.

Telegram does not get calendar access in phase 8.

No calendar MCP server is introduced in phase 8.

Calendar event ids are generated by the store.

Timestamps must be timezone-aware ISO 8601 datetimes.

Cancel is a soft delete.

There is no hard delete in phase 8.

## Consequences

Calendar data is inspectable with normal shell tools.

The index can be rebuilt from the event log.

The event log preserves historical write evidence.

Calendar data stays protected under SAFEPLANE_HOME/data.

Future assistant calendar tools can be built on top of this store through a narrow validation boundary.

The design may later move to SQLite or another database if querying, transactions, recurrence, or sync requirements become more complex.
