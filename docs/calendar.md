# Calendar store and assistant tools

Safeplane provides a deterministic local calendar store plus harness-brokered
calendar MCP tools. The model never writes calendar files directly.

## Storage path

```text
${SAFEPLANE_HOME}/data/calendar
```

Layout:

```text
events.jsonl
index.json
snapshots/
backups/
```

`events.jsonl` is the append-only source of truth. `index.json` is rebuildable.
Event IDs are generated by the store and use the `cal_evt_<uuid>` form.

Calendar timestamps must be timezone-aware ISO 8601 values, for example:

```text
2026-07-22T09:00:00+02:00
```

## Direct operator commands

Create an event:

```bash
./scripts/safeplane calendar create \
  --title "Planning block" \
  --start "2026-07-22T09:00:00+02:00" \
  --end "2026-07-22T10:00:00+02:00"
```

List a day or week:

```bash
./scripts/safeplane calendar list --day "2026-07-22"
./scripts/safeplane calendar list --week "2026-07-20"
```

Show or cancel one event:

```bash
./scripts/safeplane calendar show cal_evt_<uuid>
./scripts/safeplane calendar cancel cal_evt_<uuid>
```

Rebuild and snapshot:

```bash
./scripts/safeplane calendar rebuild-index
./scripts/safeplane calendar snapshot
```

Cleanup and reset help:

```bash
./scripts/safeplane calendar cleanup --help
./scripts/safeplane calendar reset --help
```

Reset requires explicit confirmation and creates a backup of the current event
log and index first.

## Assistant boundary

The `assistant` workflow may call these validated tools through the harness MCP
broker:

```text
calendar_list
calendar_create
calendar_cancel
```

The `calendar-task-mcp` service receives only the calendar data and MCP log
mounts. It has no provider, GitHub, or Telegram credential and no external
egress. The `chat` workflow has no calendar permission.

Notifications are separate validated objects. The assistant may schedule a
message or calendar digest through the notification MCP service; the scheduler
renders due work and routes delivery through configured connectors.
